# Документация ProperDocs + MaterialX

## Рабочий процесс

1. Прочитай `properdocs.yml` перед добавлением нового синтаксиса.
2. Определи тип страницы: пост, справочная страница или индекс.
3. Для поста используй front matter проекта:

```yaml
---
date: YYYY-MM-DD
description: Краткое описание
tags:
    - Tag
categories:
    - category
slug: readable-slug
---
```

4. Напиши или измени контент, сохраняя существующие ссылки, якоря и стиль.
5. Используй Markdown и включённые расширения вместо произвольного HTML.
6. Проверь страницу по чек-листу ниже.
7. Запусти `properdocs build`. Для визуальной проверки используй `properdocs serve`.

## Правила разметки

- Один `#` на страницу; разделы — `##`, подразделы — `###`.
- Внутренние ссылки — относительные Markdown-ссылки; важные якоря задавай явно через `{#anchor}`.
- Код оформляй fenced-блоком с языком: ` ```ts `, ` ```python `, ` ```bash `.
- Admonition, вкладки, details и Mermaid требуют отступа в 4 пробела для вложенного содержимого.
- Изображения подключай относительными путями и с описательным alt-текстом.
- Не редактируй `site/`: это результат сборки.

## Быстрые шаблоны

````markdown
!!! warning "Важно"

    Условие или ограничение.

=== "npm"

    ```bash
    npm install package
    ```

=== "pnpm"

    ```bash
    pnpm add package
    ```
````

Подробнее о доступных конструкциях см. [reference.md](reference.md).

## Чек-лист

- [ ] Front matter корректен и соответствует соседним страницам.
- [ ] Заголовки образуют последовательную и единственную иерархию.
- [ ] Ссылки и изображения используют правильные относительные пути.
- [ ] У изображений есть alt-текст.
- [ ] У каждого code fence есть язык и закрывающий fence.
- [ ] Вложенные MaterialX-блоки отформатированы четырьмя пробелами.
- [ ] Примеры кода соответствуют тексту.
- [ ] Выполнен `properdocs build`.
